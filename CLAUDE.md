## 5. File formats (pipe-delimited)

```
users.txt        : id|hashed_password|name|role|email|contact|status
                   role ∈ {Manager, Technician, CounterStaff, Customer}
                   status ∈ {ACTIVE, DELETED}  ← soft delete pattern
appointments.txt : appointmentId|serviceType|status|scheduledDate|totalAmount|customerId|technicianId|staffId
                   status ∈ AppointmentStatus enum {PENDING, IN_PROGRESS, COMPLETED, PAID}
payments.txt     : paymentId|appointmentId|customerId|amount|paymentDate (yyyy-MM-dd HH:mm:ss)
feedback.txt     : feedbackId|rating|customerName|comment|date
services.txt     : id|name|category|description|price       ← currently EMPTY
```

ID prefixes: `M` Manager, `T` Technician, `C` CounterStaff, `CU` Customer, `A` Appointment, `P` Payment, `F` Feedback, `S` Service.

## 6. Conventions you must follow

1. **FileHandler paths**: pass **only the filename** (e.g. `"users.txt"`), never `"data/..."` or `"src/database/..."`. `FileHandler` prepends `data/` itself. There is currently a bug in `FeedbackController` and `ServiceController` where this is wrong — needs fixing.
2. **Passwords**: always store SHA-256 hashed via `utils.PasswordHasher.hashPassword()`. Never plain-text. Compare hash-to-hash, not plain-to-hash.
3. **Soft delete**, not hard delete, for users — flip the `deleted` flag and write back. Already wired in `StaffController.deleteStaff()` and the red-row renderer in `ManageStaffPanel`.
4. **Storable interface**: any model that goes to a text file should implement `services.Storable` and define `toFileFormat()`.
5. **Polymorphism**: `User` is abstract with abstract `getDashboardAccess()` — every subclass overrides it. Keep this pattern; it's evidence for OOP marks.
6. **Java 21 idioms are encouraged**: switch expressions (`switch (role) { case "Manager" -> ...; }`), text blocks (`"""…"""`), `var`, pattern matching. Already used in `LoginPanel`, `StaffController`, `PaymentController`.
7. **GUI styling**: existing palette is purple `#6464F8` (RGB 100,100,248) for primary buttons, light slate `#B0C4DA` (176,196,218) for headers, soft red `#C8303C` (200,48,60) for delete. Match this so the Manager pages stay consistent.
8. **Navigation**: ManagerDashboard uses `CardLayout`; new panels are added via `contentArea.add(panel, "VIEW_NAME")` and shown via `cardLayout.show(...)`. The `Dashboard.switchContent(viewName)` method is the public entry.

## 10. OOP evidence inventory (for the report)

Tag this when writing/refactoring so I can cite it later:

- **Abstraction**: `models.User` is `abstract`; abstract `getDashboardAccess()` forces subclass logic. `services.Storable` interface for any persistable model.
- **Inheritance**: `Manager`, `CounterStaff`, `Technician`, `Customer` all `extends User`.
- **Encapsulation**: all model fields `private`, accessed via getters/setters. Password is hashed before being assigned.
- **Polymorphism**: `getDashboardAccess()` overridden per subclass; `LoginPanel` uses runtime type via switch on role string to instantiate the right `User` subclass; `FileHandler.writeData(...)` is overloaded (single record vs full list).
- **Enum usage**: `AppointmentStatus` replaces stringly-typed status — counts as an OOP/type-safety improvement.
